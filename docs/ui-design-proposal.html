界面设计方案 v2

基于现有页面的优化提案 · 2026-09-22 · 交付对象：前端实现

本方案不推翻现有界面。它建立在一件已确认的事实上：视觉语言（硬边纸玩）已经收敛完毕，缺的不是颜色，是秩序。所以下面 90% 的内容是「把已经做对的东西补齐守卫规则」，10% 是「把顺序和门槛改掉」。

P0

3 条硬缺陷

焦点环四套颜色且全部低于 WCAG 2.2 的 3:1；弱化文字在 23 个表面里 15 个不达标；顶栏把「停留分钟」当指标 —— 与产品立场直接冲突。

P1

5 条习惯冲突

首屏不是主行动；不可点的卡片长得像可点；两套解锁口径；8 个 h1；三个页面三套底色。

增量

设计系统 5 个补丁

--on-* 配对、--muted 修正、统一焦点环、--btn-drop-lg、断点收敛到 3 档。全部给到可直接粘贴的值。

§0一页读懂

结论依据（可复现）
颜色不用改，规则要补主色 --ink #173f37 在全部 21 个浅色表面上都 ≥4.5:1（最差 4.79 在 coral 上）。缺的是「哪个底色配哪个文字色」的配对令牌，现在靠 44 个手调硬编码色在打补丁。
焦点环是当前最明确的达标缺陷四套焦点色实测：--coral 2.33:1 / #92b74e 2.21:1 / #237d9a 4.49（纸）/3.93（奶油）/ video 的 #cbbbf8。WCAG 2.2 SC 1.4.11 要求 ≥3:1 → 全部不达标。
「时长」是立场问题，不只是文案问题顶栏 #reputation-stat 显示 activeSeconds/60，学习页悬浮钟显示「本次 0:00」，而家长端自己写着「时长不用于解锁」——已察觉冲突但没解决。
首页的问题不是丑，是顺序DOM 顺序：两块外链样板课卡 → 店铺 hero → 任务地图。孩子要滚过两块装饰才看到「今天学什么」。
不能再加组件了，先给组件加状态35 个 button、13 个 section，但只有 7 个 aria-label、1 个 aria-live；成就页 4 张徽章卡是写死在 HTML 里的死代码。

§1他们「习惯」什么

「符合用户习惯」对这个产品有两层含义，两层的动作经常互相矛盾 —— 儿童要少，家长要多且可核查。所以先把两边的习惯拆成可验收的判据，再谈界面。

用户 A · 8–12 岁孩子

习惯与对策

习惯设计判据
不预读文字，先看「哪儿能点」每个视口必须有一个明确最高优先级的可点物；装饰卡不可长得像按钮
单任务视野，一次只看一件事一屏一条对齐轴；同屏最多 3 个信息块
手眼协调未成熟，点不准主控件 ≥52px，紧凑控件 ≥44px；可点区含 padding
靠结果反馈学习，不靠解释判定后 200ms 内出现视觉反馈；反馈先给结论再给理由
对「我错了」敏感，会关掉页面禁用红叉 + 「错误/失败」；用「再想想」+ 引导式追问
会自己去点任何看起来能点的东西语言切换、清档等破坏性操作必须加门槛；锁态必须写清「怎么解锁」
无时间感，但有「还剩多少」焦虑儿童端零倒计时、零停留计时
用户 B · 25–45 岁家长（真正的付费决策人）

习惯与对策

习惯设计判据
碎片时间扫读，只看标题和小结家长中心结论前置：先给「今天他做了什么」，再给解释
要「我该做什么」，不要「我们很用心」必须有可执行产出（今晚可以聊什么），不做纯理念陈列
对儿童产品默认不信任安全边界要写在数据旁边，不是写在另一页
关心时长，但不该被时长驱动时长只在家长端、且明确标注「不作为解锁与评价依据」
会截图转发给伴侣家长端单屏可截图即完整（≤1 屏）
这条最容易被忽略：家长要时长、孩子不该看见时长 → 结论是同一个数据两种呈现，而不是「删掉时长」。顶栏那个数字改掉，家长中心补上，冲突就解了。

§3设计原则 · 6 条

每条都写成「可验收的判据」，而不是口号。这才是能在代码评审里用的东西。

原则 1

一屏一件事，行动在首屏

判据：每页首个主 CTA 在 100vh 内，无需滚动。首页信息块同屏 ≤3。

原则 2

要么可点，要么说明为什么不可点

判据：任何带描边 + 硬边 + 图标的元素必须响应点击；锁态必须带锁图标 且 写清解锁条件。

原则 3

反馈先结论、后理由，且不评判

判据：文案禁用「错误/失败/错/笨」；用「再想想 / 差一点」。判定后 200ms 内出反馈。

原则 4

文字有配对，颜色不兼职

判据：每个填充色都有 --on-*；文字对比 ≥4.5:1，非文本（焦点、图标）≥3:1；饱和底不承载弱化文字。

原则 5

目标够大，节奏有公共分母

判据：儿童端主控件 ≥52px；同屏相邻块间距只取 --sp-* 五档。

原则 6

时间不进孩子的视野

判据：儿童端零倒计时、零停留计时、零「你已学习 X 分钟」；时长只出现在家长端，并标注不作为评价依据。

§4设计系统 v2 · 5 个补丁

全部是增量，不推翻现有 49 个令牌。每个值都算过对比度，可直接粘贴进 styles.css :root。

补丁 1 · --on-* 配对令牌（解决 P0-2）

实测结论比预想的干净：--ink 一个值就能覆盖所有浅色表面，所以配对表可以很短。真正需要修的是「弱化文字」那一档。

两条硬规则（写给实现，避免再次手调）：
① 饱和填充（lime / coral / blue / purple / yellow）禁止白字 —— 实测白字最低 1.16:1（on lime），最高也只有 2.43:1（on coral）。这些底只承载 --ink。
② 饱和填充禁止弱化文字 —— 因为饱和底的明度都落在中间，比 ink 更浅的前景一律不达标（--muted 最好也只有 4.28:1 on lime）。所以「辅助说明」只允许出现在纸底与淡底色上。
③ --muted 从 #61746f 换到 #4f6d67（= ink 混白 24%），最差从 4.02 → 4.58，一眼看不出变深，但把 15 处失败清零。

补丁 2 · 统一焦点环（解决 P0-1）

结论：没有任何单一颜色能在所有表面上过 3:1（实测 coral 底上连深橙都只有 1.54:1）。所以采用「按表面明暗二选一」而不是调色。

浅色表面 · 全部达标
outline: 3px solid var(--ink); outline-offset: 2px;
21 个浅色表面实测 4.79 – 11.65 : 1，最差也超 3:1 一档有余。
深色表面 · 换白环
.on-dark :focus-visible { outline-color: var(--white) }
ink 底 11.65:1 · deep 底 14.25:1

同时删掉 #92b74e、#237d9a、#cbbbf8 三个焦点色，新增 --focus: var(--ink) / --focus-on-dark: var(--white) / --focus-width: 3px / --focus-offset: 2px，五个 CSS 文件统一引用。

补丁 3 · 主按钮补一档按压量（解决 README §4 ⑥）

落地页主按钮 · 76px / 7px 边
卡片式主控件 · ≥46px / 4px 边
工具栏紧凑控件 · 40–48px / 3px 边
新增 --btn-drop-lg: 7px。原来 .primary-button 写死 5px（hover 4 / active 5），既不成档也没名字 —— 现在按压量 = 边缘高度这条物理规则在三档里都成立。

补丁 4 · 标题档落地（解决 README §4 ③）

把 --fs-h1 / --fs-h2 从固定值改为流式，页面就不必绕开 token 写 clamp()：
--fs-h1: clamp(26px, 3.4vw, 34px);
--fs-h2: clamp(22px, 2.6vw, 28px);
--fs-h3: 22px;　→ 三处页面标题改回吃 token，token 表与实际用法重新对齐。

§5组件规格 · 真实渲染

下面不是示意图，是可直接对照实现的 DOM 与状态。每块都给规格注释。

5.1 按钮三档 · 全套状态

主 = lime 底 + --deep 边；次 = 白底 + ink 边；文字 = 无底无边的下划线。 禁用态收掉硬边（box-shadow: 0 0 0）——「看着能按但按不动」是最常见的儿童挫败点。 Tab 到任意一个看焦点环（ink 3px）。

5.5 语言分段控件 · 加门槛（解决 P2-10）

现状 · 一次点击即切

提案 · 长按或家长区才可切

做法：顶栏的分段控件改为只显示当前语言（不可点），切换能力移到家长中心；或保留控件但要求长按 1 秒（与家长中心入口同一个意图确认模式）。

5.6 家长话术卡 · 新增组件（真正的复访理由）

先肯定

「你今天算利润的时候，是先看成本再定价的，这个顺序对的。」

具体到动作，不评价孩子本人

再提问

「如果奶茶涨到 8 枚星币一杯，你还会先买包装吗？」

换一个数字问同一件事，检验是否真懂

生活延伸

「超市里同样的水，为什么大瓶反而每毫升更便宜？」

把课堂概念接到真实场景

这是家长中心唯一有回访价值的产出，必须预置在课程数据里（parent.talk[3]），不做 AI 实时生成 —— 质量可控，且不把儿童数据发出去。每课三张，卡片本身要能单屏截图。

5.7 空态 · 成就页

★
还没有徽章，这很正常

徽章会在你完成课程里的挑战后出现。第一枚「利润小侦探」在第一课结束就能拿到。

规格：空态必须给出下一件事（一个可点按钮），而不只是解释。文案不给期限、不制造「你落后了」。

§6页面级改造方案

6.1 经营地图首页 —— 问题在顺序

现状 · 主行动在第三块
① 零花钱小镇（外链）→
② 思维样板课（外链）→
③ 店铺 hero + 三个统计
④ 任务地图 ← 真正的主行动
⑤ 后续商业场景（不可点）
提案 · 主行动提到首屏
① 继续学习：当前课名 + 进度 + 开始 →
② 任务地图（横向 4 节点，弱化已完成项）
③ 店铺 hero（缩为一条状态条）

  • 新增「继续学习」条：读存档算出下一个未完成节点，文案是「接着上次：第一次采购」，按钮直达。这是 8–12 岁用户最需要的唯一信息。
  • 店铺 hero 降级：它现在占了一整屏（minmax(320px,.75fr) 的插画列），功能是氛围。保留视觉但压缩到一条横向状态条。
  • .coming-worlds 二选一：要么每张卡加按钮变成「我想玩这个」的投票（顺带产出真实的用户偏好数据），要么整块移除。现状「长得像入口但点不动」是最差的选项。

6.2 顶栏 —— 撤掉时长，补上「今天做了什么」

现状 3 个统计
  • 0 / 6 课（footsteps）
  • 0 分钟（stopwatch）← 与立场冲突
  • LV.1 等级（star）
提案 3 个统计
  • 0 / 6 课（不变）
  • 今日「发现」计数，如 2 件事（不用时间单位）

§13新增 · 启动页礼花

需求是「给首页加个彩纸特效，让它看上去更精美」。随需求一起给的是一份 React + shadcn + Tailwind 的组件集成说明 —— 与本项目的技术栈完全不兼容，照搬只会产出一堆跑不起来的死代码，所以只保留了效果本身，用本项目的方式重写。

13.1 为什么不引 canvas-confetti

栈不匹配（逐项核对）：组件要 React（forwardRef/useRef/createContext）、要 TypeScript（.tsx + import type）、要 Tailwind 的 className、要 shadcn 的 /components/ui 与 @/lib/utils 别名，还要 npm i 三个包。本项目的实际状态是：package.json 零依赖（只有一条构建脚本），components/ src/ lib/ 目录都不存在，无 tsconfig、无打包器。
而且会撞构建断言：build-private.mjs 要求 dist/ 顶层恰好等于白名单（多一个文件即失败），往产物里塞 .tsx 不只是无效，会直接把构建搞挂。
决定：手写。项目约定是零第三方运行时依赖，全站唯一例外是 vendor/lottie（只服务「星币到账」，取舍已记档）。礼花是纯装饰，不值得再开第二个例外 —— 这条效果真正需要的只是「一批带重力的矩形纸片」，手写不到 200 行。

13.2 实现（confetti.js，20260922-13）

形态：左下与右下两门炮对射，两轮齐射（88 + 60 片），约 2.5 秒自然落尽后画布自行销毁，页面上不留常驻节点。
触发：app.js 的 showStartScreen() 里 setTimeout(…, 260) —— 延后一拍让 hero 先落位，同时起跳会互相抢注意力。API 是通用的 window.mqConfetti.cannons()，日后要用在别的高光时刻直接调即可。
设计一致性：配色不写死在 JS 里，从 :root 读设计令牌（--lime/--coral/--blue/--purple/--yellow/--white/--ink），改令牌即改彩纸；形状只有矩形／方片／飘带，「翻面」靠横向压缩模拟自转，不做 3D 透视 —— 与方向 A 的硬边纸片是同一套语言。
接线四处缺一不可：index.html 脚本表（排在 app.js 之前）、build-private.mjs 的 assets（21 → 22 项）、sw.js 的 CORE_FILES、以及换缓存戳。新增脚本文件不换戳 = 老缓存里旧 HTML 去引一个不存在的文件。只有 index.html 引它 —— 思考站与零花钱小镇不加载 app.js，不需要。

13.3 降级与无障碍（硬约束）

  • prefers-reduced-motion: reduce 命中 → 连画布都不创建、不启 rAF（不是「放慢」）。优先于页面设置，与全站既有的 5 处降级同一口径
  • 画布 aria-hidden="true" + pointer-events:none：不进 tab 序、不吃点击。实测视口中心 elementFromPoint 从未命中它，「开始学习」按钮照常可点
  • 纯装饰，不往 #a11y-announcer 写任何东西 —— 读屏用户听到的仍是页面本身
  • 任何异常静默吞掉：礼花挂了绝不能挡住「开始学习」这个唯一出口

13.4 验收（drive-confetti.js，CDP 版）

§14新增 · 星币实体系统与结课仪式（游戏感改造 · 第一刀）

用户判断：产品「有点廉价」「太像做题，不像游戏」，第一章内容深度不足。拆解后的结论是：画面不丑（方向 A 的视觉语言已经成立），缺的是游戏感三支柱 —— 没有可操作的东西、没有场景、没有高光时刻。钱这个财商游戏的绝对主角，此前只是一行数字和圆点字符。参考了 Explore Prespa（插画场景热区 / 按压 squash / 有生命的物件 / 通关证书）的交互语法，全部零依赖移植。

14.1 新模块 coins.js（20260922-14）

只做一件事：在两个「区」之间搬运星币，把搬运做出手感。window.MoneyCoins.mount(host, config) —— 手动模式（币是按钮，点一枚动一枚，孩子自己凑数）与自动模式（币是装饰 span，由 setCounts() 按商品成本驱动）。 飞动用「量旧位 → 重挂 → 量新位 → 从旧位飞过去」的 FLIP 写法；带一点回弹的缓动（cubic-bezier(.2,.7,.3,1.25)）。
状态零存储：分布完全由调用方（lessons.js 的进度对象）给出，重挂载原样恢复 —— 本模块不碰 localStorage。

14.2 硬币声与按压手感

硬币声：TeachingMedia.playCoin()（teaching-media.js）—— 三角波高频双击（约 1.9–2.4kHz，两次随机微移音高）， 与答对 chime 共用 AudioContext 但用独立的 tones 池（硬币连响不掐断答对音）；静音偏好共用一把闸，AudioContext 未解锁时安静放弃。 为什么放 teaching-media：静音状态不该有两个主人。新模块只借用，不另建存储。
按压：.mq-coin:active = 拍扁（scale .9）+ 沉进底边 —— 与全站按钮 --btn-drop 同一套物理语言；入场后第一枚币「请」一次（单次 wobble），不做常驻呼吸动画（会和 ：active 打架）。

14.3 第 1 课重做：「亲手数、亲手付」

第 2 步从「2 选 1 选择题」改为三段式付款场景（新练习类型 payScene，视觉区即场景）： 数钱（10 枚逐枚点进柜台，数字是孩子数出来的）→ 付钱（恰好 6 枚才成交；差/多只是托盘摇一摇 + 状态行说明， 币留在原地让孩子自己调整 —— 错误由物件暴露，不由文字批评，且不触发对白、不重渲染）→ 货架（果汁 3 可买；贴纸 5 会把托盘画出虚线缺口位，「买不起」由装不满这个物理事实讲出来），最后才出现原来的选择题 —— 此刻孩子带着刚数出的缺口作答。对白按相位切换（dialogues.js 的 paySceneChats）。 一节课的真实决策点从 2 个升到 7–9 个。

14.4 购物篮长出星币托盘 + 复习变体

所有 basket 类练习的视觉区改为「还没花的 / 准备付」双区币场：加减货时币按成本自动飞进飞出， 过关时「准备付」区的币先付给店家（逐枚飞走），再落答对庆祝 —— 钱的动作在前，奖励在后。 购物篮改成就地更新（不再整页重渲染），否则币的飞动每次都被 innerHTML 重置。
复习变体：open() 在「再次查看」时置 p.variant = 1，challenge 可带 variants 数组 （第 1 课换成郊游：水 2 + 面包 4 必需、小礼物 4 想要、预算 8）—— 第二次是练习而不是默写。首学永远用主版本。

14.5 结课仪式（峰终定律的「终」）
