# 03 · 学习页（课程播放器）★ 本次重点

**文件**：`index.html` → `#mission-layer` > `#guided-lesson`，内容由 `lessons.js` 渲染
**样式**：`dialogue.css` 末尾「学习页排版」一节（全部限定在 `body.is-lesson` / `#guided-lesson`）+ `styles.css` 的 `.lesson-*`

---

## 1. 页面目标

六节基础课的教学主体。一节课 = 五个阶段，孩子每屏只做一件事。

这一页要同时扛住三个身份：**动画书**（故事）、**老师板书**（示范）、**练习册**（动手）。
改版的核心命题就是：不要让这三个身份同时说话。

## 2. 五个阶段

| 步 | 名称 | 内容 | 主按钮 |
|----|------|------|--------|
| 1 | 故事时间 | 小芽 / 团团对白讲情境（可朗读） | 一起看看 → |
| 2 | 陪你看一遍 | 星币分步演示：`跟着星币看变化`，一画面一句对白 | 下一小步 → / 我来试一下 → |
| 3 | 一起试试 | 练习（我第一次做，有提示） | 看看我的选择 / 开门试一试 |
| 4 | 这次我来 | 换情境的挑战（无提示，独立完成） | 换个情境，我来试试 → |
| 5 | 我的发现 | 结论 + 回家可以问家长的一个问题 | 带着发现回地图 → |

**答对一次 = 一颗学习星星**（复习也算）。星星**不是钱**，也不能兑换任何东西 —— 文案里写死了这条。
**答错不阻断**：错误反馈给的是「我们一起看看」，不是扣分；没有红色错误态。

## 4. 排版问题与改造对照（第一轮：收中轴）

> 第二轮「上图下题」见文件末尾，那份对照表管的是**顺序**，这张表管的是**排布**。

改版前的诊断：**这一屏有四个块同时在抢注意力**（sticky 顶栏、大课头卡、五步标签条、对白角色条），孩子要滚过三块内容才读到故事的第一句；而真正的题目又被 ≥900px 的双栏布局和对白、演示拆到左右两侧。

| # | 位置 | 改版前 | 改版后 | 为什么 |
|---|------|--------|--------|--------|
| 1 | 顶栏 | 「任务进度」文案 + 进度槽 + 计数，与五步标签条表达同一件事 | 课程页隐藏「任务进度」标签，只留进度槽 + 计数；顶栏高度 72 → 60px | 同一信息写两遍，等于两遍都要读 |
| 2 | 课头卡 | 图标 92px、`h1` `clamp(34px,5vw,56px)`、`--e3` 9px 硬边 —— 读起来像「封面」 | 图标 52px、`h1` `clamp(21px,2.6vw,27px)`、`--e2` 6px 硬边 —— 读起来像「页头」 | 封面占半屏却只承载一个标题，故事被推到首屏之外 |
| 3 | 五步标签条 | 当前步 = 深底白字，已完成 = 亮绿，未到 = 白底 ink 边：三档都很「实」，视线被已完成吸走 | 当前步 = **亮绿 + ink 描边 + 900 字重**；已完成 = 浅底 ink 字；未到 = 纸底灰字 | 视线应当落在「我正在哪一步」 |
| 4 | 演示阶段（第 2 步） | ≥900px 时 `grid` 双栏：左列对白、右列标题+演示+按钮 | **单栏**，先读完对白再看演示 | 把故事和数字拆到两侧，孩子要来回扫视；单栏一次只看一件事 |
| 5 | 对白角色条 | 两个 128px 头像一个贴左一个贴右，中间夹一句装饰小字；窄栏里挤成三层 | 两个 64px 头像**并排靠左**，装饰小字隐藏，**当前说话者不透明、另一人降到 45%** | 宽度还给气泡；孩子一眼看出「现在是谁在说」 |
| 6 | 朗读控件 | 夹在「对白」和「要动手做的事」之间，占一整块 | 压成气泡正下方的**一行**（听 / 停 / 声音与动画设置），背景与边框去掉 | 读完故事不该越过一排播放控件才看到题目 |
| 7 | 动作区 | 主按钮与提示按钮并排、宽度接近，主按钮 `margin-top:18px` 吊在半空 | 主按钮收成 **460px 居中通栏**，提示退成它下方一行小字按钮 | 一屏只有一个「大按钮」；两个同重量按钮会让孩子犹豫 |
| 8 | 对齐 | 标题靠左、对白居中(720px)、按钮回到左边缘 —— 三套对齐同时存在 | 全页统一到 **720px 阅读中轴**（`margin-inline:auto`） | 一屏之内只允许一条对齐轴 |
| 9 | 垂直节奏 | 14/18/22/24 混用 | 统一到 `--sp-1 ~ --sp-5`（8/12/16/24/32） | 垂直节奏没有公共分母 = 读起来「乱」 |
| 10 | `.lesson-bottom` | 「← 再看一遍」靠左、说明文字跟在后面 | 整行居中，与中轴对齐 | 与主按钮同轴 |

## 6. 儿童适配原则（本页的硬约束）

| # | 原则 | 落地方式 |
|---|------|---------|
| 1 | 一屏一件事 | 单栏 + 单一大按钮；主按钮居中 460px |
| 2 | 大目标 | 主按钮 `min-height:52px`（学习页）／选项按钮 `min-height:56px`；紧凑控件 ≥44px |
| 3 | 字大行疏 | 正文 `--fs-body`(18px) / 行高 1.9；对白 `clamp(20px,2.2vw,23px)` / 行高 1.7 |
| 4 | 说话的人看得见 | 当前说话者不透明 + 轻微上移，另一人降到 45% |
| 5 | 不用红色报错 | 错误反馈是 `--coral` 左侧强调条 + 「没关系，我们一起看看」 |
| 6 | 随时能停 | 顶栏常驻「暂停休息」，弹出遮罩后内容 `inert`；连续学习 15 分钟出现一次休息提醒（非强制） |
| 7 | 不倒计时、不断签 | 全页无倒计时；「本次 0:00」只累计不提示；时长**不用于解锁任何内容** |

## 7. 状态清单

| 状态 | 表现 |
|------|------|
| 朗读中 | `root.is-narrating`，说话者头像上下轻微浮动（1.1s 循环）；受「减少动画」开关与 `prefers-reduced-motion` 双重约束 |
| 朗读不支持 | 状态行提示「这个浏览器暂不支持朗读，可以看字幕和演示」，文字与无声演示仍可用 |
| 已静音 | 朗读按钮禁用；文字与演示不受影响 |
| 答对 | `TeachingMedia.celebrate()` 插入 `.answer-reward`（星星 +1），并给主按钮让出焦点 |
| 答错 | `.lesson-feedback`（无 `success`）显示 coral 强调条；可重试，`attempts` 只记录不惩罚 |
| 已通过（`p.passed`） | 选项按钮 `disabled`，出现下一步按钮 |
| 复习（`state.completed[id] === true`） | `open()` 把该课进度重置回第 1 步，不覆盖其他课的进度 |
| 视频已配片 | 第 1 步多出一张 `.lesson-video` 播放卡；未配片时 `MoneyVideo.slot()` 返回空串，页面与配片前完全一致 |
| 暂停 | `#study-pause` 遮罩 + `.mission-content` 设 `inert`，进度保存 |

# 第二轮改造 · 上图下题（参考多邻国的学习页骨架）

**动机**：第一轮把这一屏从「四块抢注意力」收成了一条中轴，但**顺序**没动 ——
视觉内容（视频 / 星币演示）都排在课头、五步条、对白、朗读按钮**下面**。
第 1 步配了片的课上，孩子要滚过一整屏文字才发现「这里有一段视频」。
多邻国的骨架相反：**上方是这一屏的图或视频，下方才是题目与操作**。
这一轮把顺序改成「先看，再做」，并顺手把课头与选项一起收一档。

## 一、舞台拆成两段

`.lesson-stage` 现在只有两个孩子：

| 区块 | 回答的问题 | 装什么 |
|------|-----------|--------|
| `.stage-visual` | 这一屏**要看什么** | 视频卡 / 星币分步演示 / 角色舞台（三选一） |
| `.stage-task` | 这一屏**要做什么** | 对白（此时读作题目引导语）、题目控件、反馈、动作按钮 |

视觉区三种内容按优先级取一种：

| 优先级 | 条件 | 内容 |
|---|---|---|
| 1 | 这一步配了片（`MoneyVideo.slot()` 非空） | `.lesson-video` 播放卡：封面、播放、时长、跳过、文字版、AI 标注 |
| 2 | 第 2 步「陪你看一遍」 | `.teaching-animation` 星币分步演示 |
| 3 | 其余三步 | `.lesson-scene` 角色舞台：课图标当道具 + 小芽按情绪换表情 + 一行说明 |

**第 2 档没有改 `teaching-media.js`**：`lessons.js` 先在视觉区画一个空的
`.demo-money`，`TeachingMedia.mount()` 照旧把它整体 `replaceWith` 掉 —— 原有契约不变。
万一某课没有演示帧，留下的也是「几枚星币」这个静态画面，不会是个空盒子。

**第 3 档为什么必须有内容**：视觉区带 `min-height`。如果某些步骤什么都不放，
孩子每翻一步都要重新找视线落点。角色舞台给的是一条**新的**信息
（现在是谁、什么心情），不是把下方的题目文案再画一遍 —— 上方那张图如果只是
下方文字的插图，就退化成装饰了。

## 二、情绪与反馈接上

小芽的表情按状态走，四格全部取自已有的 `sunny-expressions.png`，没有新增素材：

| 状态 | 表情 |
|---|---|
| 听故事（第 1 步，无片）/ 刚刚答对 | `happy` |
| 轮到你做（第 3、4 步） | `curious` |
| 第 1 步（有片时用不到，无片时是开场） | `welcome` |
| 答错 | `gentle` |

答错仍然不用红色，走的还是 `--coral` 左强调条 + 「没关系，我们一起看看」。

## 三、顺手修掉的四件事

| # | 问题 | 处理 |
|---|------|------|
| 1 | 课头卡顶着 `clamp(34px,5vw,56px)` 的封面标题，首屏被它吃掉约 110px | 压成一行：图标 92 → 36px、标题回到 18px、硬边 `e3` → `e1`，整块 ≤ 68px |
| 2 | 纯文字选项横向并排，换行之后孩子要判断「上一行和这一行谁对谁」 | 改成一列等宽卡片。商品篮（basket）是「从货架上挑」、份数（quantity）是「1–5 的量尺」，各有空间语义，保持原样 |
| 3 | 窄屏五步条折成两行占约 70px | 只留当前步 + 总步数，形如「3 一起试试 / 5」，一行 31px |
| 4 | 视频清单是异步拉的、挂载点却必须同步判定「这一步有没有片」。孩子抢在清单到达前点开始，视觉区会先落到角色舞台；以前只是「少一张卡」，现在主角位是错的 |  增加 ：清单到达后只重画视觉区，不整页重渲染（重渲染会把对白打回第一句） |

**第 3 条背后是个真 bug，值得记下来**：改完之后窄屏课头量出来仍然是 80px。
排查发现 `dialogue.css` 的文件末尾另有一个更早写的 `@media (max-width:650px)` 块，
里面也有 `#guided-lesson .mission-title` 与 `.lesson-steps` 规则。它在**源码顺序上晚于**
新加的「学习页排版」一节，同优先级下直接胜出。删掉被接管的那 5 行后才恢复正常。
教训：给一个文件末尾追加新一节时，先全仓搜一遍同一选择器 —— 媒体查询不提供特异性加成，
**后来者赢**，与它在不在 `@media` 里无关。

**第 4 条修的过程中挖出  自己的一个 bug**： 记忆的是
`manifestRequested` 这个布尔值，而不是那个请求。所以第二次调用会**立刻 resolve 出当时还是空的
清单** —— 调用方以为自己等到了。
`app.js` 初始化时已经 `preload()` 过一次，课程里再调一次拿到的就是空清单，
于是「第 1 步该有视频」这件事永远不成立。改成记忆 promise 后，六次冷启动全部命中。

| 选项纵向等宽 | `#guided-lesson .lesson-choices:not(.basket-choices):not(.quantity-choices) { display:grid }` |
| 窄屏步骤条 | `#guided-lesson .lesson-steps li { display:none }` + `li[aria-current]` + `ol::after { content:"/ " attr(data-total) }` |

两条容易踩的坑：

1. `#guided-lesson .mission-title` 的 `position:relative`、`.learning-star-count` 的
   `position:absolute` **必须留着**。星级角标是绝对定位的，抽掉定位它会落回网格里，
   把已经压成一行的课头重新撑成两行。
2. 旧的「每个元素各写一次 margin」一串（`.demo-heading` / `.lesson-choices` /
   `.lesson-wallet` / `.lesson-feedback` / `.teaching-animation` / `.lesson-hint`）
   全部撤掉了，否则会与 `> * + *` 打架 —— 而且它们特异性更高（`(1,2,0)` vs `(1,1,0)`），
   会静默赢。垂直节奏只能有一个公共分母。

## 五、实测高度

无头 Chrome，`--dump-dom` 抓 `getBoundingClientRect`，「声音与动画设置」收起状态：

| 视口 | 课头 | 步骤条 | 视觉区（第 1→5 步） |
|------|------|--------|---------------------|
| 1280×1005 | 65px | 31px | 521 / 345 / 240 / 240 / 261px |
| 500×805 | 60px | 31px | 400 / 309 / 193 / 193 / 181px |

首屏判断：**五个阶段里视觉区都完整可见**；桌面第 2–5 步、窄屏第 3 步的首个可点项也在首屏内。

各阶段视觉区高度不同是设计如此：第 1 步有视频时由 16:9 决定（桌面约 400–520px）；
第 2 步是星币演示，被内容顶高；第 3、4 步只是舞台，上限压到 212px。

**没做到的事**：第 1 步配了片时，「接着看故事 →」按钮在桌面要再滚 51px。
接受 —— 那一步该按的是视频封面里的「看视频」，它在首屏内。
