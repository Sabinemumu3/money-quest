# 05 · 家长中心

**文件**：`index.html` → `#parent-view`（`data-game-view="parent"`）
**样式**：`styles.css` → `.simple-view` / `.parent-grid` / **`.parent-panel`（本次新增）** / `.danger-button`

---

## 1. 页面目标

家长打开这一页要能回答三个问题：**在教什么？边界在哪？我怎么陪？**

同时它是全站唯一的「本机设置」去处 —— 场景、昵称、清除进度都在这里。

## 2. 区块顺序

| # | 区块 | 内容 |
|---|------|------|
| 1 | 标题 `.page-heading` | eyebrow「家长中心」+ `h1`「这个游戏在教什么？」 |
| 2 | `.parent-grid`（3 张白卡） | 01 从孩子的问题出发 / 02 安全边界 / 03 看看是否真的理解 |
| 3 | **`.parent-panel` 本机角色设置**（本次新增） | 场景切换（奶茶店 / 美甲店）+ 游戏昵称 |
| 4 | `#parent-progress` `.learning-notice` | 「基础课完成 n / 6；本机累计有效学习约 N 分钟。**时长不用于解锁。**」 |
| 5 | `.danger-button` | 「清除本机进度并重新开始」 |

### 2.1 为什么新增第 3 块

首次进入页精简为单一入口后，原来住在那里的**场景选择**和**昵称输入**不能跟着一起消失 —— 否则美甲店场景和昵称功能将彻底不可达（功能回归）。

把两者放到家长中心是权衡后的位置：

| 备选 | 判断 |
|------|------|
| 保留在入口页 | ✗ 与「入口只有一个按钮」直接冲突 |
| 放进侧栏当独立视图 | ✗ 为一个选填项多开一个一级导航，成本过高 |
| **放在家长中心** | ✓ 家长本来就会打开这页；切场景是「设置」性质的动作，不是孩子要做的决定 |

贴的文案刻意写清副作用：「场景只改变店铺名称、采购材料和顾客故事，**已完成的课程记录会保留**」——避免家长以为换场景会重来一遍。

## 3. 排版与组件规格

| 组件 | 规格 |
|------|------|
| `.parent-grid` | `repeat(3,1fr)` / ≤900px 单列；白底 + `--bw` ink 描边 + `--radius-lg`；序号圆点 38px 深底白字 |
| `.parent-panel` | `max-width:780px` + `margin-top: var(--sp-4)`；白底 + ink 描边 + `--radius-lg` + `--e2` 硬边；内边距 `clamp(20px,3vw,30px)` |
| 场景选择器 | `.career-choice` 复用首次进入页的组件；`grid-template-columns: 1fr 1fr`（宽屏两列） |
| 昵称输入 | `.nickname-field`，`max-width:420px`，`min-height:47px` |
| 危险操作 | `.danger-button` 浅红底 + 红描边，`--radius-sm`，**不加硬边**（刻意不做成更想按的样子） |
| 正文 | 卡片内说明 `--fs-ui`(16px)，主说明 `--fs-sm`(14px) |

### 3.1 三张说明卡的文案要点（不可删减）

| 卡 | 必含信息 |
|----|---------|
| 01 从孩子的问题出发 | 六课的学习顺序；每课的「故事 → 示范 → 陪练 → 换情境自己试」结构；**股票仅作课后拓展** |
| 02 安全边界 | 不使用真实股票 / 实时行情 / 真实资金；不收集学校、地址、出生日期、家庭收入 |
| 03 看看是否真的理解 | 建议家长问的两个问题；**做过练习 ≠ 完全掌握**；12–15 分钟是试测安排，不是统一的注意力上限；允许更慢、暂停和复习 |

## 4. 排版检查结论

| # | 项 | 结论 |
|---|----|------|
| 1 | 新 panel 与 `.parent-grid` 的关系 | 三张卡是「解释」，panel 是「设置」，两者性质不同 —— 用不同的容器形状（无硬边的解释卡 vs 带 `--e2` 硬边的设置面板）表达差别 ✅ |
| 2 | `#parent-progress` 的位置 | 它夹在设置面板与危险按钮之间，是一段 `role` 缺失的普通 `<p class="learning-notice">`。位置合理（进度 → 清进度），但**它不是提示而是数据**，用「左侧 coral 强调条」的提示样式会误导 ⚠️ 建议换成 `.lab-summary` 那类数据条 |
| 3 | 危险按钮与设置面板相邻 | 中间只隔一段进度文字，误触风险偏低但存在。`window.confirm` 已有二次确认 ✅；建议再加 8px 以上的视觉分离 |
| 4 | 与首页互斥 | 家长中心缺少「回到孩子的视角」的显式入口，家长看完要自己去点侧栏「经营地图」 ⚠️ |
| 5 | 卡片序号 | 序号圆点用 `--font-ui` 无字号声明，继承 `body` 18px，与 38px 圆点比例合适 ✅ |

## 5. 交互

| 动作 | 结果 |
|------|------|
| 点场景卡 | `state.scenario = 选项` → 立即 `saveState()` + `renderAll()`（店名、店招、材料、顾客故事全部随之切换）→ 家长中心内的选中态同步（✓ + 加粗描边） |
| 输入昵称 | 实时写入 `state.nickname` 并同步侧栏玩家卡；清空则回落到「小小店长」/「Money Explorer」 |
| 清除本机进度 | `window.confirm` → 删除 `future-life-skills-money-game-v1` **与** `money-quest-media-preferences-v1`（后者含「坏片黑名单」，不清会导致修好的视频永远不再尝试）→ `location.reload()` |
| 进入本视图 | `renderPlayer()` 会回填场景选中态与昵称输入框（`document.activeElement !== input` 时才回填，避免打断正在输入） |

## 6. 验收清单

- [ ] 家长中心能看到场景切换器，且当前场景有选中态（✓ + 加粗描边）。
- [ ] 切换到美甲店后：侧栏头像变 💅、首页店名变「彩虹美甲屋」、店招变 NAIL STUDIO；**成就页的完成记录不变**。
- [ ] 昵称输入后侧栏玩家名同步；刷新后仍保留。
- [ ] 「清除本机进度」弹确认框；确认后回到首次进入页（只剩一个「开始学习」按钮）。
- [ ] 三张说明卡在 ≤900px 单列，文字不截断。
- [ ] `#parent-progress` 里的分钟数与成就页星星数不冲突（一个说时间，一个说练习次数）。
- [ ] 页面上没有任何收集儿童真实身份信息的输入项。

## 7. 待确认

3. 是否需要把「本机累计学习时长」做成家长可关闭的项（时长不是 KPI，展示它容易被当成 KPI）。
