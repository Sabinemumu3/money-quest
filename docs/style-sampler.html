风格取样板 · 三个方向，同一套 DOM

三个面板内部的 HTML 完全相同，差异只来自每个方向顶部那几十行 CSS 令牌。这不是效果图，是真实渲染。

请重点看：按钮按下去的手感（手指按住不放）、当前章节节点是不是一眼能找到、金额数字在变值时的稳定性、以及整体是「纸片手作」还是「软陶玩具」还是「色块海报」。

投票前请先读这一条：本机没有安装任何圆体字体（已核验注册表，183 项字体里圆体为零）。所以方向 B 想表达的「圆润」在本机会回退到微软雅黑，只能看到形状与阴影的差异，看不到字形差异。这正是审计报告 §2.2 那条发现——要真正看到 B 的圆体，得先把字体子集落地。
取样板同时暴露了一个问题（这本身是审计结论）：三个方向并非所有差异都能靠令牌切换。下面这些组件我不得不写方向专属规则，说明它们还没有被令牌化：
  • 按钮：三个方向的按钮结构差异太大（硬边 / 双层阴影 / 纯色块），无法用同一组令牌表达，各写了 3 条规则
  • 星币：A/C 是圆形、C 又是方角，圆角令牌覆盖不到「圆形」这个语义
  • 进度条填充：B 需要渐变，C 需要纯深色，各写一条
  • 对话气泡圆角：现有代码用 23px 手写值（dialogue.css:23），我改成了 --bubble-radius 令牌；这属于本次新增
结论：颜色与圆角已经能靠令牌切换，但按钮与星币的「材质」还不能。这是方向定下来之后要补的令牌层。

推荐：A 为基线，吸收 B 的按压曲线与 C 的色彩纪律。理由落在现有资产而不是「更现代」这类空话：
① 现有代码里已经有一整套 4px 4px 0 var(--ink) 硬投影 + 墨绿实心描边（styles.css:98 / :152 / :168 / :186 / :234），选 A 是把已有的东西统一，不是换风格；
② 吉祥物「小芽」「团团」是硬边手绘插画，与 A 同源、与 B 相斥；
③ B 的软阴影会削弱文字边缘锐度，而我们此刻最要紧的恰好是把 45.8% 的小字号救回来；
④ 从 B 只借一件东西：cubic-bezier(.34,1.56,.64,1) 的按压回弹，用在按钮与星币上——这正好补上现在全站只有 6 处 :active 的缺口；
⑤ 从 C 借色彩纪律：一个色面只承担一个语义，用来约束那 149 个一次性色值。
