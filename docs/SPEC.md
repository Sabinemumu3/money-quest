| 项目 | 结论 |
| --- | --- |
| 一句话定位 | 让 8–12 岁孩子在模拟经营游戏里练会"怎么花钱、怎么留钱"，同时告诉家长"今天该陪孩子聊什么" |

## 1. 背景与问题

### 1.1 为什么做这件事

家长对"财商"的焦虑是真实且高企的，但市面上可选项高度两极化：

- **一端是内容课**：短视频讲道理、绘本讲概念。孩子看得懂，但**没有决策、没有后果**，看完就忘。家长无法判断孩子是否真的会了。
- **另一端是成人金融工具下沉**：模拟炒股、虚拟盘交易类产品。**合规风险极高**，且会把"投资赚快钱"的认知提前植入未成年人（本会议已明确否决，见 8.1）。

中间地带是空的：**一个让孩子自己做选择、自己承担虚拟后果、并且让家长看得见的练习场**。

### 1.2 用户痛点（本产品的立足点）

| 角色 | 痛点 | 表现 |
| --- | --- | --- |
| 家长（核心痛点） | **不知道怎么培养** | 知道财商重要，但只会说"要节约""别乱花钱"，没有可执行的方法 |
| 家长 | **不知道教得对不对** | 教完之后没有任何反馈信号，不知道孩子是真懂还是背下来了 |
| 家长 | **不知道什么时候教什么** | 缺少按年龄递进的内容阶梯，要么太难要么太幼稚 |
| 家长 | **孩子不听自己的** | 亲子关系的天然张力，家长的话自带"说教"属性 |
| 孩子 | **觉得谈钱很无聊** | 说教型内容无参与感，没有"我在做主"的感觉 |
| 孩子 | **现实中不让试错** | 家长不敢让孩子真的拿钱去犯错，孩子也就永远学不会 |

> **结论**：本产品的第一性任务是服务家长——**给家长一套"上手就能用"的方法 + 一个"看得懂"的反馈**。孩子端的游戏化是达成这个任务的手段，不是目的。

### 1.3 为什么是游戏化 + 游戏simulation

孩子愿意重复做的事只有两件：**有即时反馈的**、**自己有控制权的**。模拟经营天然满足这两点：
孩子自己决定买什么、进多少货、留多少钱，系统立刻给出钱变多/变少/不够的结果。**错误只花虚拟币，不花真钱**——这是家长允许孩子试错的唯一前提。

## 2. 产品定位与目标

### 2.1 定位

> **一个"孩子玩、家长懂"的家庭财商练习场。**
> 孩子：在模拟经营游戏里做真实的金钱决策，犯错只花虚拟币。
> 家长：拿到一份"孩子今天怎么想的"观察记录，以及今晚可以聊的 3 个问题。

**不是**：职业规划产品、金融投资入门产品、在线课堂。
模拟情境（奶茶店、美甲店、野餐预算）只是**孩子能理解的教学载体**，产品目标始终是财商与基础商业判断力。

### 2.2 目标用户

| | 主用户：孩子 | 决策者 / 共育者：家长 |
| --- | --- | --- |
| 年龄 | 8–12 岁 | 30–45 岁 |
| 设备 | 共享的平板 / 家长手机 | 自己的手机 |
| 使用时段 | 放学后、周末，单次 12–15 分钟 | 晚上查一次，单次 ≤ 3 分钟 |
| 能力假设 | 会加减法；识字量可支撑短句；**不输入真实姓名、学校、地址、生日** | 愿意为"确定有效的教育内容"付费 |
| 真实动机 | 好玩、有进度、有奖励 | **缓解焦虑**、拿到可执行方法、看到孩子的真实反应 |
| 流失节点 | 第 1 次卡关、第 1 次无聊、家长不给设备 | 第 1 周没看到"孩子有变化" |

**双用户设计原则**：孩子端**零门槛、零文本负担、零等待**；家长端**结论优先、方法可抄、不增加操作负担**。两端不共用同一套界面语言。

### 2.3 价值主张

- **对孩子**：这是我的店，我说了算。赚了钱是我的，花光了也是我的。
- **对家长**：今天孩子做了一个选择，我把他的真实反应和 3 个聊天问题给你了——不用你会教，照着聊就行。

### 2.4 业务目标与成功指标

**MVP 阶段的唯一目标：验证"孩子愿意再来一次，家长愿意为此付费"。**

| 层级 | 指标 | MVP 目标值（待确认） | 说明 |
| --- | --- | --- | --- |
| 激活 | 完成第一章第 1 节的比例 | ≥ 70% | 从进入首页到完成首节 |
| 留存（北极星） | 7 日内完成 ≥ 3 节的家庭比例 | ≥ 40% | **家庭**为单位，不是孩子个人 |
| 粘性 | 单家庭周活跃天数 | ≥ 3 天 | 对标多邻国的习惯养成 |
| 家长价值感 | 家长中心查看率 | ≥ 50% | 家长是否真的在用 |
| 家长价值感 | 家长中心"今晚可以聊"点击/展开率 | ≥ 30% | 判断这个功能是否是真需求 |
| 付费意愿 | 完整体验第一章后表示愿意付费的家长比例 | ≥ 25% | **意愿调研**，非真实支付（无后端） |
| 反指标 | 单次会话时长超过 20 分钟的占比 | 应低 | 时长**不是**目标，过长说明设计存在问题 |

> **明确否定"使用时长"作为核心指标**：本产品的教学立场是"一次只学一节、学完就休息"（见现存 `PRODUCT_BLUEPRINT.md`）。用时长做 KPI 会直接把设计带向成瘾机制，与合规边界冲突。

### 2.5 非目标（本期明确不做）

1. ❌ 真实股票、真实行情、真实基金、真实资金托管与交易
2. ❌ 任何形式的收益承诺、收益排行、杠杆/杠杆类玩法暗示
3. ❌ 儿童真实身份信息（姓名/学校/地址/生日/家庭收入/照片）
4. ❌ 开放式 AI 自由聊天（儿童端）、麦克风录音
5. ❌ 社交功能：好友、PK、排名、公开榜单、未成年人 UGC
6. ❌ 账号体系与跨设备同步（MVP 阶段，见 §9.3）
7. ❌ 真实支付（MVP 阶段，见 §5.6）

## 3. MVP 范围界定

### 3.1 范围决策

会议结论："网页端优先、首个章节验证、纯前端、快速产出可演示 Demo。"

据此确定：

| | 内容 |
| --- | --- |
| **In Scope（MVP 必做）** | 第一章（3 节完整课）｜**节前趣味视频（每节 1 段 60–120 秒，接互动练习形成「视频 + 小游戏」）**｜角色对话 + 设备语音朗读｜分步教学动画｜虚拟奖励体系（经验/星星/徽章墙）｜家长中心（观察记录 + 共育建议）｜本机进度存档｜移动端优先响应式｜PWA 可安装与离线 |
| **Partial（做但降级）** | 中英双语（英文界面走通主流程，样板课可暂缺英文）｜海外适配（先做语言 + 时区无关设计，不做本地化支付） |
| **Out of Scope（本期不做）** | 后端、账号、真实支付、App 上架、社交、内容运营后台、**AI 视频自动生成流水线**（成片以线下制作 + 手工登记上线） |
| **Next（第二章之后）** | 第二 / 第三章内容｜AI 生成教学视频的自动化流水线｜订阅支付与鉴权｜App 封装（iOS/Android）｜跨设备同步 |

> **视频已纳入 MVP**（2026-09-22 决策反转）。技术口子已落地：`video-lessons.js` · `video.css` · `media/video/`，契约见 `docs/VIDEO-MODULE.md`。

### 3.2 内容重组：把现有 6 节重组为 2 章 × 3 节

现有代码已有 6 节完整课程，但**没有"章节"这一层**。会议要求的"第一个章节"需要一个明确的内容单位。建议重组如下（**待确认**）：

| 章节 | 节 | 教学目标 | 现有资产 |
| --- | --- | --- | --- |
| **第一章 · 认识我的钱**（MVP·免费） | 1-1 我的钱有多少？ | 数钱、购买、余额 | 现有第 1 课 ✅ |
| | 1-2 先买哪一样？ | 需要 vs 想要 | 现有第 2 课 ✅ |
| | 1-3 卖到的钱都是赚的吗？ | 收入、支出、利润 | 现有第 3 课 ✅ |
| **第二章 · 经营我的钱**（付费解锁） | 2-1 今天准备几份？ | 备货、余货、机会成本 | 现有第 4 课 ✅ |
| | 2-2 给愿望留一点钱 | 储蓄、延迟满足 | 现有第 5 课 ✅ |
| | 2-3 计划变了怎么办？ | 取舍、迁移应用 | 现有第 6 课 ✅ |
| **拓展**（不占章节进度） | 小芽思考站 / 零花钱小镇 / 虚拟市场实验室 | 元认知、家庭延伸 | 现有 ✅ |

**含义**：MVP 的"第一章"= 现有前 3 课 + 新增的章节层（章节封面、章节进度、章节完成证书）。**新增开发量极小，是本次最高性价比的范围决策。**

## 5. 功能需求（EARS 规范）

> **EARS 写法说明**：每条需求以固定句式表达，保证无歧义、可测试。
> - **Ubiquitous（普遍）**：`系统应…` — 始终成立的约束
> - **Event-driven（事件驱动）**：`当 [事件] 时，系统应…`
> - **State-driven（状态驱动）**：`当 [状态] 期间，系统应…`
> - **Unwanted（异常）**：`如果 [异常条件]，那么系统应…`
> - **Optional（可选）**：`在 [可选特性] 情况下，系统应…`
>
> 优先级：P0 = MVP 必须有；P1 = MVP 应有；P2 = 后续版本。

### 5.1 FR-LESSON 课程学习

| ID | 类型 | 需求 | 优先级 | 现状 |
| --- | --- | --- | --- | --- |
| FR-L01 | Ubiquitous | 系统应在每一节的每个步骤中，持续显示孩子当前可支配的虚拟金额，且该数值必须与该步骤所属"钱袋"完全一致。 | P0 | ✅ 已实现 |
| FR-L02 | Event-driven | 当孩子提交一次练习作答时，系统应在 300ms 内给出对错判定，并展示**针对该具体答案**的解释，而非通用对错提示。 | P0 | ✅ 已实现 |
| FR-L03 | Event-driven | 当孩子完成一节的最后一个环节时，系统应结算本节经验与星星，并在章节地图上把该节标记为已完成。 | P0 | ✅ 部分（无章节层） |
| FR-L04 | State-driven | 当练习处于"预测"阶段期间，系统应隐藏总价/最终结果，直到孩子提交预测为止。 | P0 | ✅ 已实现（思考站） |
| FR-L05 | Unwanted | 如果孩子选择的物品组合超出预算，那么系统**不应**扣款、**不应**显示负余额，并应明确指出差额。 | P0 | ✅ 已实现 |
| FR-L06 | Unwanted | 如果孩子答错，那么系统**不应**扣减星星、**不应**使用责备性文案或负面音效。 | P0 | ✅ 已实现 |
| FR-L07 | State-driven | 当孩子中途退出后重新进入时，系统应恢复到上次所在的节与步骤，且已完成内容不重复发放经验与星星。 | P0 | ✅ 已实现 |
| FR-L08 | Optional | 在浏览器支持语音合成的设备上，系统应提供"听小芽讲"的朗读开关、语速调整、逐句重播与静音。 | P0 | ✅ 已实现 |
| FR-L09 | Unwanted | 如果设备无可用的中文语音，那么系统应保留完整文字与无声演示，且**不应**阻断学习流程。 | P0 | ✅ 已实现 |
| FR-L10 | Event-driven | 当孩子进入一节课程时，系统应展示熟悉的教学伙伴（小芽/团团）引导的对话式开场，而非纯文字说明页。 | P0 | ✅ 已实现 |
| FR-L11 | State-driven | 当孩子在一节课程中连续两次答错时，系统应主动提供更具体的脚手架提示，而不直接给出答案。 | P1 | ⚠️ 现有为被动"查看提示" |
| FR-L12 | Ubiquitous | 系统应在每一节末尾提供"我的发现 + 家庭小活动"，把课堂结论迁移到真实生活情境。 | P0 | ✅ 已实现 |
| FR-L13 | Event-driven | 当孩子完成一章的全部节次时，系统应发放该章完成徽章，并解锁下一章。 | P1 | ❌ 待开发（章节层） |
| FR-L14 | Ubiquitous | 第一章应在**不登录、不输入任何真实身份信息**的前提下完整可玩。 | P0 | ✅ 已实现 |

### 5.2 FR-REWARD 虚拟奖励

| ID | 类型 | 需求 | 优先级 | 现状 |
| --- | --- | --- | --- | --- |
| FR-R01 | Ubiquitous | 系统应把奖励分为两类且严格隔离：**经验/等级**（解锁用）与**学习星星**（行为记录用）。星星不可消费、不可兑换、不代表学习效果或真实投资能力。 | P0 | ✅ 已实现 |
| FR-R02 | Event-driven | 当孩子首次成功完成一道练习时，系统应发放固定 +1 星星与短提示音；复习可再得星星，但同一题的"已通过"状态不重复结算经验。 | P0 | ✅ 已实现 |
| FR-R03 | Unwanted | 系统**不应**使用抽奖、开箱、随机掉宝、连胜惩罚、倒计时、排名比较等成瘾性奖励机制。 | P0 | ✅ 已实现 |
| FR-R04 | Ubiquitous | 系统应提供可持续查看的"徽章墙"，展示每节对应的能力徽章（如「会数钱」「分得清需要和想要」「看得懂利润」）。 | P1 | ⚠️ 部分（徽章为派生渲染，无独立墙） |
| FR-R05 | Event-driven | 当孩子完成一节时，系统应展示"本节徽章 + 一句话能力说明"，让家长也能看懂这个徽章代表什么能力。 | P1 | ❌ 待开发 |
| FR-R06 | State-driven | 当孩子当日已完成目标节数期间，系统应温和提示"今天发现的不少了，去玩点别的吧"，并**不**提供继续游玩的额外奖励。 | P1 | ⚠️ 现有 15 分钟休息提醒 |

> **FR-R 设计立场说明**：会议决定"引入虚拟奖励机制"以提升粘性。但现有产品的安全边界明确禁止成瘾机制。二者并非矛盾——**多邻国的可借鉴之处是"路径感 + 进度可见 + 每天一点点"，不是"断签惩罚 + 焦虑驱动"**。本 Spec 采用前者。

### 5.3 FR-PARENT 家长中心

| ID | 类型 | 需求 | 优先级 | 现状 |
| --- | --- | --- | --- | --- |
| FR-PA01 | Ubiquitous | 系统应提供一个仅在本机可访问的家长中心，入口不得出现在孩子的主学习路径上造成干扰。 | P0 | ✅ 已实现 |
| FR-PA02 | Event-driven | 当孩子完成一节课程后，家长中心应自动生成一条该节的观察记录，包含：做了什么选择、预测与实际的差异、是否使用提示、是否改变过方案。 | P1 | ⚠️ 仅记录事实，未成条目 |

### 5.6 关于"纯前端"与"会员订阅"的技术冲突（重要）

会议同时决定了两件事，但二者在技术上互斥：

> ① "纯前端实现，暂不涉及后端开发"
> ② "产品采用基础免费 + 会员订阅的盈利模式"

**订阅必须依赖：支付通道 + 订单校验 + 权益下发**，这三件事无法在纯前端可信地完成（纯前端可被任意绕过）。

**建议的两阶段处理（待决策，见 §11 Q-02）**：

| 阶段 | 做法 | 目的 |
| --- | --- | --- |
| MVP（本期） | 不接真实支付。第二章默认**可见但标注"即将开放"**；用「兑换码 / 白名单链接 / 家长意向登记」验证付费意愿 | 保住"纯前端"承诺，同时拿到真实付费信号 |
| Phase 2 | 接入后端 + 支付（微信/支付宝/Stripe）+ 订阅权益校验 | 真实商业化 |

> 若坚持 MVP 期就要有真实付费，则"暂不涉及后端"这一决策**必须**被推翻。这个取舍需要老板拍板，不能由执行层默认。

## 7. 验收标准

### 7.1 功能验收（MVP 交付门禁）

1. **第一章 3 节全部可完整通关**，含对话、动画、练习、发现与家庭活动。
2. 每一道练习的**正误判定、数学计算、账目自洽**均通过自动化回归（现金 = 初始 − 支出 + 收入；利润仅扣售出部分成本；余货仍计库存）。
3. **超预算不扣款、不显示负余额**；**答错不扣星、无负面音效**。
4. 刷新页面后**不重复发放**经验与星星，且能恢复到上次步骤。
5. 中英文界面下第一章全流程无未翻译文本、无溢出。
6. 320px / 390px / 768px / 1440px 四个宽度下**无横向滚动**。
7. 静音、无中文语音、开启"减少动态效果"三种降级环境下，**学习流程不中断**。
8. 家长中心可正确展示每一节的观察记录与 3 条共育建议；无数据时展示引导态。
9. 未解锁章节对**孩子端**只出现"去问问爸爸妈妈"，不出现价格与支付入口。
10. `build-private` 产出的测试包**仅包含白名单文件**，且无任何自带儿童数据。

### 7.2 可用性观察（非"效果证明"）

- **样本**：5–8 个 8–12 岁孩子的家庭。
- **方法**：现场观察，不指导、不代答。
- **记录**：成人的提示次数、孩子读不懂的词、实际操作时长、换题后能否解释原因、隔日能否复述。
- **红线**：此样本量**不得**用于宣称教学效果。任何对外表述必须写清"内部可用性观察，非效果验证"。

### 7.3 上线门禁（公开收费前必须完成）

- [ ] 儿童可用性测试完成并修复理解障碍
- [ ] 家长服务条款、隐私政策、退款说明
- [ ] 未成年人个人信息保护合规声明（中国区）
- [ ] 儿童隐私声明（海外区）
- [ ] 受保护的访问控制（防止未授权访问）
- [ ] 支付与订阅权益校验（如本期要做真实付费）

## 8. 合规与安全边界（不可谈判）

### 8.1 已决策的否决项

> **在线真实股票市场功能——存在诱导未成年人投资的违规风险，决定不予采纳。**（会议决议）

**执行要求**：现有代码中的虚拟市场实验室必须复核确认其为**纯虚构情境**（三个预设情境、100 独立实验点、无真实行情源、无真实资金）。若存在任何真实数据接口或真实标的名称，**必须在本期移除**。

### 8.2 教育产品定性

产品对外应始终定性为**财商启蒙教育产品**，不得表述为：
- 投资教育 / 投资启蒙 / 理财培训
- 任何含"收益""回报""增值"暗示的表述
- 任何将游戏内成绩与"投资能力"挂钩的表述

### 8.3 儿童数据

- 不收集、不上传、不共享儿童个人信息
- 数据仅存本机浏览器；清空浏览器数据即清空记录（须在家长中心明确告知）
- 第三方配音/视频服务仅接收经审核的**课程文案**，绝不含儿童昵称、答题记录或家庭数据
- AI 生成内容须在家长端标注

### 8.4 内容安全

- 所有公司、价格、货币与市场事件均标注虚构
- 不出现消费主义诱导、攀比、物质崇拜内容
- 不出现对"花钱"或"存钱"的单一价值判断（花钱与存钱都不能单独作为财商高低的标准）

## 附录 B：EARS 需求模板速查

| 类型 | 中文句式 |
| --- | --- |
| Ubiquitous | 系统应始终…（无触发条件的持续约束） |
| Event-driven | 当 [事件] 时，系统应… |
| State-driven | 当 [状态] 期间，系统应… |
| Unwanted | 如果 [异常条件]，那么系统应… |
| Optional | 在 [可选特性/配置] 情况下，系统应… |

**写法要点**：一条需求只描述一个可验证的行为；主语统一为"系统"；避免"友好地""适当地"等不可测试的形容词；数量、时限、阈值必须写具体数字。
